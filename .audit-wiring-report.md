# Dashboard wiring audit — 2026-05-18

Scope: `packages/dashboard/src/` only. Goal: find every piece of canned /
hardcoded / mock content that should have been live data from the daemon,
and wire it up.

## Issues found

### 1. Brainstorming was canned (`BrainstormPage.tsx`)

- A baked-in `QUESTION_POOL` of seven French question buckets, paired with
  a per-resonance-mode `ORDER_BY_MODE` that drove the chat with scripted
  questions.
- A scripted "Loom analyse le projet existant" intro with a fake feature
  audit (`FEATURE_ANALYSIS`, `FEATURE_REPORT_MD`) that pretended to read
  the project's stack ("React 19 + Vite", "~62% test coverage", ...).
- `POST /chat` was only reached after the canned plan was exhausted; in
  practice users never got a real Loom reply during the brainstorm phase.

### 2. CLI runtime detection was static (`WizardPage.tsx`)

- `DEFAULT_CLI_STATE` hardcoded `claude-code: { installed: true,
  authenticated: true, version: "1.4.2" }`, `copilot:
  installed=true,authenticated=false,version=0.4.0`, `codex:
  installed=false`, then cached the lie in
  `localStorage["loomflo.cliDetection"]`.
- `GET /runtimes/availability` was untouched (the hook
  `useRuntimeAvailability` already existed in Phase B but wasn't used).
- Effect on a fresh install: the wizard let users pick "Claude Code
  (OAuth)" as primary provider even on machines without the CLI.

### 3. LoomChatPanel never talked to the daemon (`LoomChatPanel.tsx`,
   used in `WorkflowPage.tsx`)

- The panel ran `detectIntent` + `buildResponse` from `loomBrain.ts`, a
  regex-based intent detector that returned hand-written replies and
  fake "action cards" instead of calling the chat API.
- `WorkflowPage` only consumed `useChat.messages` to render history but
  never invoked `useChat.send`, so user actions were stubs.

### 4. SettingsPage "Réinitialiser le workflow" was a lie

- The danger-zone reset button only showed a toast (`"Workflow
  réinitialisé"`) — no daemon endpoint exists for this, no state was
  cleared.
- The page-header subtitle said "Toutes les modifications sont
  enregistrées localement" even though `diffLocalConfig` →
  `updateConfig` already pushes changes to `PUT /projects/:id/config`.

### 5. Stale baseline test

- `test/context/ProjectStoreContext.test.tsx` still asserted that the
  offline fallback hydrated from a non-empty `SEED_PROJECTS`. After
  `e2852c9b` scrubbed the seed to `[]`, the test had been failing on
  `main` (1 failure was already in baseline).

## What was fixed

- **`fix(dashboard): detect CLI runtimes from daemon instead of static list`**
  Replaced `loadCliDetection`/`saveCliDetection`/`DEFAULT_CLI_STATE` in
  `WizardPage.tsx` with `useRuntimeAvailability()`. The wizard now shows
  "Non installé" / "Non connecté" until the daemon answers, then
  reflects the real environment. Removed the localStorage cache that
  could persist false-positive availability between sessions.

- **`fix(dashboard): wire brainstorm to /chat endpoint`**
  Stripped `QUESTION_POOL`, `ORDER_BY_MODE`, `buildQuestionPlan`,
  `FEATURE_REPORT_MD`, `FEATURE_ANALYSIS`, `askNextQuestion`, and the
  `runIntroSequence` scripted dance from `BrainstormPage.tsx`. The page
  now hydrates from `GET /chat/history` on mount, routes every user
  message through `POST /chat`, streams replies at ~40 chars/sec (the
  constitution rate), and shows a "Lance le daemon" notice when no
  token is available. The resonance picker stays as a cosmetic
  threshold for when the "Lancer la spec" CTA unlocks.

- **`fix(dashboard): route LoomChatPanel through /chat in WorkflowPage`**
  Added optional `onSendMessage` + `liveMessages` props to
  `LoomChatPanel`. When supplied (now done by `WorkflowPage`), the
  panel sends messages through the parent's `useChat.send` and renders
  the live history instead of running its local regex detector.
  `useChat.send` now returns the assistant reply (and rejects on
  error) so the panel can stream it. The local `detectIntent` path is
  preserved for back-compat with the panel's unit tests.

- **`fix(dashboard): remove fake workflow-reset action and stale offline test`**
  Removed the "Réinitialiser le workflow" entry and its modal from
  `SettingsPage`, rewrote the page subtitle to acknowledge the
  daemon-backed sync, and updated `ProjectStoreContext.test.tsx` to
  assert the empty-state behavior the SPA actually ships.

## Out of scope / not fixed

- **`loomBrain.ts` regex intent detector**: kept verbatim so existing
  unit tests (`test/lib/loomBrain.test.ts`, `test/components/
  LoomChatPanel.test.tsx`) still cover the back-compat fallback path
  used when `onSendMessage` isn't supplied. The default
  `WorkflowPage` route now always supplies `onSendMessage`, so the
  user-visible chat never runs through the regex detector.
- **`SEED_MESSAGES` / `SEED_HISTORY` exports in `loomBrain.ts`**: still
  exported and referenced by the back-compat `LoomChatPanel.test.tsx`,
  but not consumed in production code paths anymore.
- **SettingsPage provider dropdown**: the `<select>` lists a static set
  of providers (Anthropic API, OpenAI API, Moonshot API, Claude Code,
  ...). Replacing with a live `GET /credentials` + `/runtimes` join is
  a larger UX change and was not requested.
- **`useChat` WebSocket dedup with `send`**: `send` already adds the
  assistant reply to its own state list; the parent panel also streams
  it from the awaited Promise. If the daemon also broadcasts
  `chat_response` (`useChat` listens for it), the dedup branch in
  `useChat` keeps the list correct. No additional dedup needed in
  `LoomChatPanel` because it uses `liveMessages` directly.
- **No daemon-side changes**: per the audit instructions, `packages/
  core/` was not touched. No new routes were added (`/chat` was
  already sufficient).
- **`/mock/*` switch**: untouched. Mock-mode (`VITE_USE_MOCK=1`) is
  still the single switch that reroutes project-scoped GETs to
  `/mock/*` fixtures via `ApiClient.resolvePath`. Offline-without-
  mock continues to render the empty offline view.

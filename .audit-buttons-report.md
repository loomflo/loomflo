# Dashboard buttons audit — 2026-05-19

`packages/dashboard/src/components/loom/LoomChatPanel.tsx`. Goal: make the
end-to-end "create a project from the dashboard, kick the workflow, watch
events live" flow actually work, and prune the buttons that pretended to
do something.

Builds on the wiring audit (commits `a4fbe771`, `cfd59cfc`, `14ef2278`,
`bff9e6b7`, report in `.audit-wiring-report.md`).

## Fixes

File-by-file diff summary (5 commits, all on `main`):

### `packages/dashboard/src/pages/WizardPage.tsx`
- `finalize()` now upserts an `anthropic-oauth` credential named
  `claude-code` when the user picks Claude Code, so the daemon's
  `profiles.get(providerProfileId)` resolves. Copilot/Codex still
  document the gap.

### `packages/dashboard/src/pages/BrainstormPage.tsx`
- `launchSpec()` now calls `api.initWorkflow(projectId, { description,
  projectPath })` with the user-side transcript as description, then
  navigates. `skipBrainstorm()` does the same (lets users skip the chat
  but still actually creates a workflow).
- New `launching` state disables the launch button mid-call.

### `packages/dashboard/src/pages/WorkflowPage.tsx`
- New "Démarrer le workflow" button visible when `wfStatus === "building"`,
  calls `api.startWorkflow(projectId)`.
- Logs button now opens an `EventsDrawer` that lists workflow events
  from `useEvents({ projectId, limit: 200 })` instead of being a no-op.
- Adds `useEvents` + `Event` type imports.

### `packages/dashboard/src/pages/NodeDetailPage.tsx`
- Removed `InstructionsModal`, the "Modifier les instructions" button,
  `onSaveInstructions`, and the `editing` state — they only fired a
  toast saying the daemon didn't support edits.

### `packages/dashboard/src/pages/SettingsPage.tsx`
- `ProvidersSection` now takes a live `options: string[]` prop built
  from `useCredentials()` plus authenticated `useRuntimeAvailability()`.
  Empty state points users back to the wizard.
- MCP modal "Ajouter" button removed the `!draft` guard so users can
  add an MCP server without first entering edit mode on the Tools
  section.

### `packages/dashboard/src/pages/ProjectsPage.tsx`
- Removed the dead Settings gear icon from `TopBar`.
- Removed the stub "Paramètres" and "Documentation" entries from the
  command palette.
- Removed the broken "Logs" nav target (route doesn't exist; logs live
  on the workflow page now).
- Renamed the palette's project-settings payload to `settings` so the
  navigate target matches the actual route.

## End-to-end flow validation

The keystone path the user asked for now works:

1. Click "Nouveau projet" on the projects page → wizard opens
2. Fill the wizard (folder, provider, level, delay, name, type)
3. Click "Créer le projet" → POST /projects (claude-code OAuth users
   also get an anthropic-oauth credential upserted)
4. Wizard "Aller au brainstorming" → navigates to /brainstorm
5. Chat with Loom (already wired)
6. Click "Lancer la génération de la spec" → POST /workflow/init,
   navigates to /workflow
7. WorkflowPage shows the daemon's live spec-gen progress
8. When the workflow transitions to `building`, the new "Démarrer le
   workflow" button appears → POST /workflow/start
9. The graph and event stream populate live via WS

## Out of scope (daemon gaps documented for follow-up)

- **Per-node instruction overrides**. NodeDetailPage's edit modal was
  removed because the daemon has no endpoint for it. A future
  `PATCH /projects/:projectId/nodes/:nodeId` with `{ instructions }`
  would close this.
- **General settings (project name / folder / template) updates**.
  The Settings page edits these locally because there's no daemon
  route for renaming a project or moving its folder.
- **Copilot CLI / Codex CLI as primary providers**. There's no oauth
  credential type for them in `ProviderProfilePayload`, so selecting
  them in the wizard still falls through to a `default` profile that
  the user has to register themselves via `loomflo credentials add`.
  Adding `copilot-oauth` and `codex-oauth` to the credential schema
  would let the wizard handle these like it does claude-code.
- **Review verdict UI**. `GET /nodes/:id/review` exists and is used by
  NodeDetailPage's logs, but there's no `POST /nodes/:id/review`
  endpoint with a `{ verdict }` body — so no approve/reject buttons.
- **Workflow reset / restart**. The "reset workflow" action was removed
  in the prior audit; the daemon still doesn't have an endpoint to
  destroy a workflow without destroying the whole project.
- **Folder existence pre-check**. The wizard doesn't verify the path
  exists on disk before submitting — the daemon validates at init time.
  A `POST /fs/exists` or similar would let the wizard fail earlier.
- **MCP edit (vs add/delete)**. The MCP modal only supports adding;
  editing requires removing and re-adding. Could be a UI-only fix.
